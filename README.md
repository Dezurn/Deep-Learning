# Умное предсказание цены по описанию и изображению товара

## О проекте

Проект посвящён автоматическому прогнозированию цены товара на маркетплейсе по данным из карточки: текстовому описанию и изображению товара. В качестве основы использованы данные соревнования Amazon ML Challenge 2025.

## Бизнес-смысл проекта

На маркетплейсах карточки заполняются лично продацом. При заполнении карточки продавец может самостоятельно указывать цену товара, которая может оказаться завышенной, заниженной или не соответствовать характеристикам продукта. Такие ошибки негативно влияют как на продажи продавца, так и на клиентский опыт. Отсюда и возникает необходимость отслеживать правильность указанной цены продавцом. В случае, если цена указана некорректно помечать данный товар в системе как подозрительный и отправлять его на дополнительную модерацию перед публикацией. Таким образом наша модель позволит нам сэкономить на модерации каждого товара по отдельности и повысит честность продавцов по отношению к потребителю и к нам как компании.

### Цель

Разработать систему автоматического прогнозирования цены товара на основе информации, содержащейся в его карточке. Для этого используются текстовое описание товара, извлечённые признаки и изображение продукта.

## Архитектура решения

Решение состоит из создания двух моделей: табличной модели по извлечённым признакам и моделей предсказания цены по изображениям товаров.

1. **Подготовка данных.** Исходные `train.csv` и `test.csv` сохраняются в `data/raw`. Из поля `catalog_content` извлекаются дополнительные признаки, после чего формируются промежуточные таблицы в `data/extracted`.
2. **EDA и подготовка табличных признаков.** В ноутбуке `EDA.ipynb` проводится анализ распределений, корреляций и категориальных признаков. После обработки формируется таблица `data/for_models/train_model_ready.csv` для обучения MLP.
3. **Подготовка данных для изображений.** Ноутбук `image_csv_generation.ipynb` формирует отдельные таблицы для моделей, работающих с изображениями, в `data/for_models`.
4. **Табличная модель.** В `MLP.ipynb` обучаются несколько вариантов MLP. Сохранённые веса, скейлеры, списки признаков и результаты экспериментов лежат в `models/mlp`. Также эксперименты логируются в DagsHub.
5. **Модели для изображений.** Обучаются ResNet18, EfficientNet и Vision Transformer. Лучшие веса сохраняются локально в `model_outputs`, а эксперименты логируются в DagsHub.
6. **Сравнение результатов.** Итоговое качество моделей сравнивается по метрикам MAE и RMSE.

## Порядок воспроизведения

1. Загрузить исходные данные в `data/raw`.
2. Запустить `notebooks/feature_extraction_train.ipynb` для извлечения признаков из тренировочной выборки.
3. Запустить `notebooks/test_csv_generation.ipynb` для подготовки тестовой выборки.
4. Запустить `notebooks/EDA.ipynb` для анализа и формирования тренировочной выборки к обучению моделей.
5. Запустить `notebooks/image_csv_generation.ipynb` для подготовки датасета к обучению моделей на картинках.
6. Запустить `notebooks/MLP.ipynb` для обучения табличных MLP-моделей.
7. Запустить ноутбуки с моделями для изображений: `notebooks/ResNet18.ipynb`, `notebooks/EfficientNet.ipynb` и `notebooks/Vision Transformer.ipynb` для обучения моделей на картинках.
8. Сравнить результаты моделей по итоговым метрикам MAE и RMSE.

## Сравнение параметров модели для табличных данных

Для табличных данных были обучены несколько вариантов MLP. Все модели использовали оптимизатор Adam и ReLU в качестве функции активации.

| Модель | Архитектура | Dropout | BatchNorm | Loss | MAE log | RMSE log | MAE price | RMSE price |
|----------|-------------|----------|------------|------|----------|-----------|------------|-------------|
| MLP_small | 88 -> 64 -> 32 -> 1 | 0 | Нет | MSELoss | 0.720 | 0.920 | 14.64 | 37.18 |
| MLP_medium | 88 -> 256 -> 128 -> 64 -> 1 | 0.1 | Да | MSELoss | 0.691 | 0.891 | 14.10 | 37.04 |
| MLP_large | 88 -> 512 -> 256 -> 128 -> 64 -> 1 | 0.2 / 0.1 | Да | MSELoss | 0.697 | 0.894 | 14.29 | 37.33 |
| MLP_Huber | 88 -> 256 -> 128 -> 64 -> 1 | 0.1 | Да | SmoothL1Loss | 0.700 | 0.901 | 14.26 | 37.29 |
| MLP_Embedding | 51 numeric features + unit embedding(8) -> 256 -> 128 -> 64 -> 1 | 0.1 | Да | MSELoss | 0.697 | 0.897 | 14.17 | 37.16 |

Лучшей моделью стала `MLP_medium`: она показала минимальные значения RMSE log, MAE log и MAE price среди рассмотренных конфигураций. Увеличение размера сети до `MLP_large` не улучшило качество. Замена MSELoss на SmoothL1Loss в `MLP_Huber` и добавление эмбеддинга также не дали прироста. Самой оптимальной архитектурой оказалась `MLP_medium` с батч-нормализацией и дропаутом.

## Сравнение моделей по изображениям

В итоге по неструктурированным данным (картинкам) были обучены 3 модели: VIT, ResNet и EfficientNet.


- ResNet: лучший RMSE = 29.81, что неплохо, но хуже EfficientNet и ViT. Это логично: Resnet18 проще по архитектуре, быстрее и легче, но хуже извлекает тонкие визуальные признаки товара. 
- EfficientNet-B0 оказался очень удачным компромиссом. Его лучший результат RMSE = 29.39, то есть он лучше ResNet18 и почти догоняет ViT. При этом модель легче и быстрее, чем ViT и EfficientNet-B2.  
- Более глубокий EfficientNet-B2 не дал прироста: RMSE = 29.61. Хоть и возжны варианты с более тонким обучением, но кардинально усиление архитектуры не дает резкого прироста в качестве. 
- Лучший результат по качеству показал ViT-v2 full-pretrain: RMSE = 29.24. Это самая сильная модель по картинкам, но она тяжелее и дольше обучается. 
- ViT-v3 дал лучший MAE = 14.34, но по RMSE уступил v2, поэтому как итоговую модель по основной ошибке лучше считать ViT-v2. 

Итог: для задачи предсказания цены по изображениям лучше всего сработали предобученные модели. Обучение с нуля давало плохие или нестабильные результаты. Среди всех image-моделей лучший результат показал ViT-v2, но так-же хорошим вариантом выглядит EfficientNet-B0: качество почти такое же, как у ViT, но модель гораздно проще.
